  - `check-layer-visibility.mjs` — layer-data visibility is decided only by the engine's

- **Project ops and command ops still share one `(peerId, seq)` counter space** — the engine now
  refuses the collision loudly (`sync/op-category.ts`; `PreAttachOpBuffer.push` throws
  `OpCategoryError`, `isCoveredByWatermark` is category-aware), but `OutboundOpStamper`
  (`apps/maker-gjs/src/services/collab-op-stamper.ts`) and `SessionController`'s command counter
  both still start at 0 under the same `peerId`. Namespace the project-op sequence — stamp the
  category on the envelope, or offset the counter — so the two families cannot collide regardless
  of routing. Today only `CollabSession`'s routing keeps them apart. *owner: maker*
- **Half the `win.*` action table is not CI-reconciled** — `window-actions.gjs.spec.ts` installs
  five of the ten `install*Actions` modules and asserts declared-set == installed-set. The other

  installed here) while `src/test.mts` builds one graph for both runtimes. Duplicate names are
  still caught everywhere (`action-registry.ts` throws `DuplicateActionError`); an action added

  or per-target spec entry points. *owner: maker + gjsify*
- **`application-window.ts` is 1080 lines**, the largest maker file after the 2026-09-05 pass.
