Still placeholders: a real in-game **dialogue / text-box overlay** for `show-text`, an **inventory bag** for `item-picked-up` (`InventoryComponent` + `item-def` library entities + `INVENTORY_CHANGED`, owned by the `inventory` game system), and an **audio layer** for `play-sfx`. Teleport is the one fully-real effect (engine `loadMap` + spawn override). *owner: engine + project layer*
- **State overlays are actions-only** — `StateSystem` swaps a matched state's `actions` list and nothing else; a state carrying `visual`, `collision` or any other type validates with a warning and stays inert. Visible cost: a door teleports once its flag is set but never *looks* open, and a chest still looks closed after it gave you its item. Doing it properly means rebuilding a live entity's overlaid components through the spawn pipeline mid-frame (sprite swap, collider swap) while keeping runtime companions like `TriggerFiredComponent` alive — the first piece of engine work in this design that rebuilds a spawned entity, so it gets its own round. Also open: the "Only when …" authoring row (the condition is editable today only through the raw `states` JSON). *owner: engine + gjs*
- **`inventory` has no bag yet** — the base system owns `item` and contributes the existing `ItemPickupSystem`, so a pickup fires and the host toasts it, but nothing holds what was picked up: no `InventoryComponent` on the session singleton, no `item-def` library entities, no `INVENTORY_CHANGED`. Lands with the first system that reads a bag. *owner: engine, why: no consumer yet — see [`docs/concepts/game-systems.md`](docs/concepts/game-systems.md) § Reach*
- **The inspector shows a field's `min`, not its `default`, when the value is absent** — `ComponentInspector` builds a `SpinRow` with `field.default` but its `set()` falls back to `field.min ?? 0`, so the SAME optional field reads one number on a freshly-seeded component and another on a loaded one that never had it written. Pre-existing and generic (every spec with an optional number), but newly conspicuous: `stats` has five, and a slime with no `expToNext` in its data displays `1` where the spec says `10`. Fix is one line in `packages/gjs/src/widgets/editor/component-inspector.ts`; it needs a test harness for that widget first, which is why it is not folded into the combat PR. *owner: gjs*
- **`combat-action` leaves three gaps** — (a) **no real game over**: a defeated hero is full-healed and given a grace period so a playtest cannot dead-end; a retry / restart flow needs playthrough save-state that survives a scene load, which does not exist. (b) **`stats.speed` is not shipped** — its only reader is `combat-turn`'s speed-sorted `TurnOrderSystem`, and in realtime combat the movement rate is already `movement.tilesPerSec`; it lands with that system. (c) **the Game-rules body still has no switch-off `Adw.AlertDialog` and no destructive "Remove data" row** — switching off is already non-destructive, so the dialog is a courtesy rather than a safeguard, but the expander was designed with both. See [`docs/concepts/game-systems.md`](docs/concepts/game-systems.md) § Reach. *owner: engine + maker*
- **Per-player input sources (gamepad / remote / AI)** — movement + input shipped: `InputSystem` polls the keyboard into the session-singleton's `InputSourceComponent` (intent vector), `PlayerSystem` consumes it and emits `player-tile-changed` / `player-action-pressed`. Remaining: the source-descriptor variant on per-player entities (see `docs/concepts/collaboration-and-multiplayer.md` § 5) once split-screen / remote players arrive. *owner: engine*
- **Scratchpad stripes inside Excalibur** — backdrop is currently a solid `--scratchpad-b` color (theme-aware). Bring back the diagonal stripes from the design via a tiled scratchpad actor in the editor scene. *owner: engine — needs an `EditorBackgroundLayer` actor*

If a future runtime needs a genuine reset (re-spawn picked-up items, rewind actor positions, drop live combat state), it belongs behind one engine method that `restart` calls — not a second runtime path in the action. *owner: engine*

## Cleanup / debt

- **A dead Yarn PnP editor SDK still advertises TypeScript 5.5 to editors** — `.yarn/sdks/typescript/` is tracked and declares `"version": "5.5.3-sdk"` with its own `lib/typescript.js`, left over from before the gjsify migration. The repo has used no Yarn since (`gjsify-lock.json`, no `yarn.lock`), so nothing in the build or CI reads it — but an editor that picks the workspace SDK gets a 5.5 language service while `gjsify foreach check` runs TypeScript 7. Diagnostics then disagree with CI in both directions, and the gap widened from one minor to two majors when TS 7 landed. Delete `.yarn/` (also `.yarn/releases/yarn-4.13.0.cjs`) unless something still needs it.
  *owner: tooling, why: leftover from the Yarn-era toolchain, harmless to the build*

- **`gjsify install --refresh-lockfile` is blocked repo-wide by a partial `@girs` 4.7.0 release** —
  four packages were published alone at `4.7.0` (`adw-1`, `cairo-1.0`, `avahi-0.6`,
  `avahicore-0.6`) while the rest of the family stayed at `4.6.0`. Each 4.7.0 declares its
  dependencies on `^4.7.0`, so resolving one demands `@girs/gjs@^4.7.0`, which does not exist.
  A refresh re-resolves every range to its newest match and dies on
  `@girs/cairo-1.0@4.7.0 ← ^4.6.0`. Cairo is **transitive** — no workspace declares it, so it
  cannot be pinned here, and gjsify has no `overrides`/`resolutions` mechanism. `@girs/adw-1` is
  pinned to an exact `4.6.0` in `packages/gjs` and `apps/maker-gjs` because we DO declare it;
  that pin stops adw-1 itself resolving to the broken release but does **not** unblock refresh.
  Consequence: in-range bumps (biome, zod, ws, the MCP SDK) cannot be picked up until upstream
  publishes the family together. Plain `gjsify install` resolves from the lockfile and is fine.
  Un-pin adw-1 and drop this entry once `@girs/gjs` reaches 4.7.0.
  *owner: external (ts-for-gir), why: a broken upstream publish, not our defect*

- **Repo guards — nine scripts in `scripts/`, all CI-gated.** Each exists because the bug class it
  covers had already shipped; add the mechanism with the fix, not just the fix.
